CoderCo · Containers and Docker

Behind the project.

A small application built to practise the parts of containerisation that matter: packaging software, connecting services, keeping data, and distributing requests.

What happens when you click?

  1. Your browser sends a request to NGINX on your Mac's exposed port.
  2. NGINX forwards the request to a Flask container listening internally on port 5000.
  3. Flask selects an emoji and writes the new count, emoji total, and anonymous browser score to Redis.
  4. The application returns the new count and Flask container hostname. The browser displays both.

Why three Flask containers?

Docker Compose runs three copies of the same Flask image. They each have their own container identity but share one Redis instance. Different container IDs between clicks demonstrate that requests reached different replicas.

What is stored?

Redis stores the total counter, emoji totals, and scores under randomly generated browser IDs. The leaderboard is a demo: it does not know a person's real name or reliably identify a person across devices.

Persistence

The Compose configuration attaches a named volume to Redis. That keeps its saved data when the Redis container is recreated, provided the volume is retained.
